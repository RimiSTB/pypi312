--------------------------------------------------------------------------------
1) WHAT IS GREENLET?
--------------------------------------------------------------------------------

greenlet is a lightweight C extension for cooperative multitasking (coroutines).
It provides:
  - Explicit context switching via .switch()
  - Send values and throw exceptions between greenlets
  - Zero-copy lightweight contexts (no stack allocation until switch)
  - Foundation for libraries like gevent, eventlet

Unlike Python's built-in asyncio (which uses `await`), greenlet uses explicit
switching - you choose exactly when to pause and resume.

    import greenlet
    print(hasattr(greenlet, "greenlet"))  # True
    print(greenlet.__version__)           # 3.2.3

3) CREATING AND SWITCHING GREENLETS
--------------------------------------------------------------------------------

    import greenlet

    # Define a worker function
    result = []
    def worker():
        result.append("started")
        result.append("done")

    g = greenlet.greenlet(worker)   # create (does NOT run yet)
    g.switch()                      # run until it finishes or yields

    print(result)    # ['started', 'done']

    # Switch back and forth:
    result = []
    def parent():
        result.append("parent_before")
        child_gr.switch()          # switch to child
        result.append("parent_after")

    def child():
        result.append("child")
        greenlet.getcurrent().parent.switch()   # switch back to parent

    child_gr = greenlet.greenlet(child)
    greenlet.greenlet(parent).switch()

    print(result)
    # ['parent_before', 'child', 'parent_after']

4) SENDING VALUES AND THROWING EXCEPTIONS
--------------------------------------------------------------------------------

    import greenlet

    # --- send ---
    def worker():
        x = (yield)       # pause, wait for value
        y = (yield)       # pause again
        greenlet.getcurrent().parent.send((x, y))

    g = greenlet.greenlet(worker)
    next(g)                    # prime the generator
    g.send(10)                 # x = 10
    result = g.send(20)        # y = 20, worker returns
    print(result)              # (10, 20)

    # --- throw ---
    def worker2():
        try:
            yield
        except ValueError as e:
            greenlet.getcurrent().parent.throw(e)

    g2 = greenlet.greenlet(worker2)
    next(g2)
    try:
        g2.throw(ValueError, "oops")
    except ValueError as e:
        print(e)               # "oops"

5) GETCURRENT AND PARENT
--------------------------------------------------------------------------------

    import greenlet

    # getcurrent returns the currently running greenlet
    me = greenlet.getcurrent()
    print(type(me).__name__)   # 'greenlet'  (the main greenlet)

    # Every greenlet has a .parent attribute
    def child():
        print(greenlet.getcurrent().parent is greenlet.getcurrent().getcurrent())
        # Actually, use:
        parent = greenlet.getcurrent().parent
        print(parent is greenlet.getcurrent())  # False (parent is main)

    g = greenlet.greenlet(child)
    g.switch()

6) DEAD STATE AND CLEANUP
--------------------------------------------------------------------------------

    import greenlet

    def worker():
        pass

    g = greenlet.greenlet(worker)
    print(g.dead)     # False  (hasn't run yet)

    g.switch()
    print(g.dead)     # True   (finished)

    # Switching a dead greenlet raises greenlet.error
    try:
        g.switch()
    except greenlet.error as e:
        print(e)      # "dead greenlet"

    # A greenlet that raises an exception is also dead:
    def bad():
        raise RuntimeError("crash")

    g2 = greenlet.greenlet(bad)
    try:
        g2.switch()
    except RuntimeError:
        pass
    print(g2.dead)    # True

7) ROUND-ROBIN SCHEDULING
--------------------------------------------------------------------------------

You can implement your own scheduler by manually switching between greenlets:

    import greenlet

    order = []

    def make_worker(name):
        def worker():
            order.append(name)
            greenlet.getcurrent().parent.switch()
            order.append(name + "_resumed")
        return worker

    g1 = greenlet.greenlet(make_worker("A"))
    g2 = greenlet.greenlet(make_worker("B"))

    g1.switch()     # A
    g2.switch()     # B
    g1.switch()     # A_resumed
    g2.switch()     # B_resumed

    print(order)
    # ['A', 'B', 'A_resumed', 'B_resumed']

8) GREENLET LOCAL STATE
--------------------------------------------------------------------------------

Each greenlet can have its own attributes (like thread-local storage, but cooperative):

    import greenlet

    def worker():
        me = greenlet.getcurrent()
        me.my_data = [1, 2, 3]
        greenlet.getcurrent().parent.switch()
        # After parent resumes us, our data is still here:
        print(me.my_data)    # [1, 2, 3]

    g = greenlet.greenlet(worker)
    g.switch()     # worker sets my_data, yields
    g.switch()     # worker reads my_data back

Note: greenlet attributes are NOT thread-safe. Each thread has its own main
greenlet; greenlets do not migrate between threads.

9) COMMON PATTERNS
--------------------------------------------------------------------------------

Pattern: cooperative task queue
    import greenlet
    tasks = []
    def run_forever():
        while tasks:
            task = tasks.pop(0)
            task.switch()

Pattern: generator-like producer/consumer
    def producer():
        yield 1
        yield 2
        yield 3

    def consumer(producer_greenlet):
        while not producer_greenlet.dead:
            value = producer_greenlet.switch()
            print("got:", value)

Pattern: wrap a callback-based API
    def on_complete(result):
        greenlet.getcurrent().parent.switch(result)

    def wait_for_callback():
        result = greenlet.getcurrent().parent  # placeholder
        # (actual usage depends on the specific API)


--------------------------------------------------------------------------------
10) PITFALLS & NOTES
--------------------------------------------------------------------------------

- greenlet does NOT automatically save/restore C stack frames. If you switch
  while inside a C extension callback, you may get crashes.
- greenlet is NOT compatible with Python's asyncio. Use gevent if you need
  both.
- greenlet does NOT provide stack switching - only the current frame is saved.
- Each OS thread has exactly one main greenlet (the one running at import time).
- Switching to a dead greenlet raises greenlet.error.
- If a greenlet raises an exception, it propagates to the parent greenlet
  (the one that switched to it).
- Wheels here are tagged cp312-cp312-linux_<ABI>. Install the correct one
  for your device ABI (arm64 or x86_64).
